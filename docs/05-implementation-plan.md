## 1. 進め方

- 作る順番を 8 つの段階（マイルストーン）に分ける。1 つの段階が終わるごとに、GitHub Pages に公開して動きを確かめる
- 各段階は 1 本のブランチで作り、プルリクエストで `main` に入れる
- 先に「スマホにインストールしてオフラインで起動できるか」を確かめる（M0）。いちばん大きなリスクを最初につぶすため
- 計算のルールは画面より先に作り、テストで固める（M1）
- 期限は決めない（DP-3）。段階の順番どおりに進める。使い始めたい日が決まったら、そこから逆算して模擬出店の時期を決め、この章に書き足す

### 1.1 始める前の準備

1. GitHub でリポジトリ名を `marche-register` に変え、公開（public）にする（04 の DT-1）
2. 手元の接続先を新しい名前に合わせる
3. ドキュメントのブランチ（`docs/requirements`）を push し、プルリクエストで `main` に入れる
4. GitHub の設定で、Pages の公開元を「GitHub Actions」にする

## 3. テストの観点

04 の 9 章で決めた方法ごとに、確かめる内容を挙げる。

### 3.1 計算（`domain/`、Vitest）

| 対象 | 確かめること |
|---|---|
| % 値引き | 3 方式の値（03 の 4.1 の表、要件定義 6.2 の 555 円の例）。0 円の商品、1% と 100%、10 円未満の金額での 10 円単位 |
| 円の値引き | 対象金額を超える値は、対象金額で止まる |
| 1 取引の計算 | 03 の 4.3 の計算例がそのとおりになる。8% だけ、10% だけ、両方の取引 |
| 税率への按分 | 余りが合計の大きい税率に行く。同じ額なら 10% に行く |
| 明細への按分 | 余りが金額の大きい明細から順に行く。同じ額なら行番号の小さい明細に行く |
| 必ず成り立つこと | ランダムに作った 1,000 通りの取引で、①`netAmount` が 0 以上 ②`netAmount` の合計 ＝ `total` ③税率別の対象額の合計 ＋「税込み」の明細の合計 ＝ `total` ④按分額の合計 ＝ 全体値引きの額 |
| 内消費税 | 1 円未満の切り捨て。税率ごとに 1 回だけ計算している |
| 取引番号 | `1103-001`、`1103-999`、`1103-1000` |
| 集計 | 取消を含めない。客単価の四捨五入。0 件のとき |
| CSV | BOM と CRLF。「,」「"」・改行を含む商品名。`=` で始まる商品名。列の順番 |
| バックアップの検査 | 違う形式、新しい版、古い版（変換される）、壊れた JSON |

### 3.2 データの読み書き（`db/`、Vitest ＋ fake-indexeddb）

| 対象 | 確かめること |
|---|---|
| 会計の確定 | 取引が保存され、`nextSeq` が増え、カートが空になる。途中で失敗させたら、どれも変わらない |
| 在庫 | 残りより多くは確定できない。取消で残りが戻る。持ち込み数を販売数より少なくできない |
| 取引番号 | 取り消した番号は使い回さない |
| 商品の削除 | 一覧から消え、カートからも外れる。過去の取引の商品名は残る |
| カテゴリの削除 | 削除していない商品があれば削除できない |
| イベントの削除 | 取引（取消を含む）があれば削除できない。削除したら持ち込み在庫も消え、現在のイベントが未選択になる |
| 復元 | 全データが置き換わる。途中で失敗させたら、元のデータが残る |
| データ移行 | 前のバージョンのデータが、新しいバージョンで読める（2 回目のデータ移行を作るときから） |

### 3.3 画面の部品（Vitest ＋ Testing Library）

| 対象 | 確かめること |
|---|---|
| お預かり | 画面設計 S-01c の例（［＋1,000］［＋500］→ 1,500 円、1,000 →「5」→ 10,005 円）。不足のとき［確定］を押せない。連打しても 1 回だけ確定する |
| 値引き | % のときだけ端数処理の 3 つを、値引き後の金額つきで表示する。定型ボタンが対象に合わせて絞られる |
| カート | 数量を 0 にすると行が消える。空のとき［値引き］［お預かりへ］を押せない |

### 3.4 操作の流れ（Playwright、iPhone と Android の画面を再現）

| # | シナリオ |
|---|---|
| E-1 | カテゴリ → 商品 → イベント → 持ち込み在庫を登録する |
| E-2 | 会計：商品を入れる → 明細と全体の値引き → お預かり → レシートの金額が 03 の 4.3 と同じ |
| E-3 | 売り切れ：残りが 0 になると押せなくなる |
| E-4 | 取消：在庫が戻り、集計から外れる |
| E-5 | カートの復元：カートに入れたまま再読み込みしても残る |
| E-6 | オフライン：一度開いたあと、通信を切っても起動して会計できる |
| E-7 | バックアップ → 全データ削除 → 復元で、元のデータに戻る |
| E-8 | CSV の中身が、会計した内容と合っている |

## 6. 模擬出店（リハーサル）

本番で使う前（M7）に、実際の商品で次の流れを通して試す。

1. 本番と同じ商品・カテゴリ・画像を登録する
2. イベントを作り、持ち込み数を入れる
3. 機内モードにして、30 件ほど会計する（値引き、売り切れ、取消を含める）
4. 集計の金額を、手で計算した金額と比べる
5. CSV を書き出して、表計算ソフトで開く
6. JSON バックアップを取り、パソコンなど別の場所にも保存する
7. 模擬出店のイベントを削除できないことを確かめ（取引があるため）、本番用のイベントを新しく作る

---

## 7. 本番で使うときの手順（おすすめ）

アプリは通知を出さないので（要件定義 F-09）、次の手順を習慣にする。

- **出店の前**：通信できる場所でアプリを 1 回開き、更新があれば更新しておく
- **出店の後**：JSON バックアップを取り、スマホ以外の場所（パソコン、クラウドなど）にも保存する
