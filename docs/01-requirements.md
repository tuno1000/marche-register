# 要件定義書：マルシェ用スマホレジ PWA

- 版：0.2
- 作成日：2026-11-05
- 状態：未決事項 Q-1〜Q-6 を決定済み。最終確認待ち

---

## 1. 概要

### 1.1 目的
マルシェ（屋外・屋内の小規模出店）で、スマートフォン 1 台を使って会計・在庫・売上記録を行えるレジアプリを作る。

### 1.2 方針
- 通信がない会場でも、すべての機能が使えること（オフラインファースト）
- アプリストアを通さず、Web から「ホーム画面に追加」して使う（PWA）
- データは端末内（IndexedDB）に保存し、サーバーは持たない

---

## 2. 前提・制約

| 項目 | 内容 |
|---|---|
| 対象端末 | iPhone（Safari）、Android（Chrome） |
| 運用台数 | 1 イベントにつき 1 台。端末間の同期は行わない |
| 操作者 | 1〜数名で同じ端末を共有。ログインは不要 |
| 通信 | 初回アクセスとアプリ更新時のみ必要。会計・集計はオフラインで動く |
| 公開 | HTTPS 必須（Service Worker の要件）。GitHub Pages を想定 |
| 決済 | 現金のみ。決済端末とは連携しない |

### 2.1 既知のリスク
| リスク | 内容 | 対策 |
|---|---|---|
| iOS のデータ消去 | Safari は条件によってサイトデータを消すことがある | ホーム画面追加を推奨する。`navigator.storage.persist()` を要求する。バックアップ機能を必須にし、前回バックアップした日時を設定画面に表示する |
| 端末の故障・紛失 | 端末内にしかデータがない | 同上（JSON バックアップ） |
| 保存容量 | 商品画像でデータが増える | 画像は保存時に縮小・圧縮する（6 章） |

---

## 3. 利用シーン

```
[事前準備（自宅・通信あり）]
  カテゴリ・商品（価格・税率・画像）を登録する
  イベントを作成し、持ち込む在庫数を入力する
        ↓
[出店当日（オフラインの可能性あり）]
  イベントを選ぶ → 会計を繰り返す → 必要なら取引を取り消す
        ↓
[撤収後]
  イベント別・商品別の集計を確認する
  CSV を書き出す / JSON でバックアップする
```

## 4. 機能要件

優先度：**MVP** = 初回リリースで必須、**後** = MVP の後で検討

### F-01 カテゴリ管理（MVP）
- カテゴリを登録・編集・削除する（名前、表示色、並び順）
- 商品が属しているカテゴリは削除できない（移動を促す）

### F-02 商品管理（MVP）
- 項目：商品名、価格（**税込・円単位の整数**）、税率（8% / 10%）、カテゴリ、画像、在庫管理の有無、並び順、販売中フラグ
- 画像はカメラで撮影するか、ライブラリから選ぶ。保存時に縮小する（6 章）
- 削除は「非表示（論理削除）」にする。過去の取引の表示が壊れないようにするため

### F-03 イベント管理（MVP）
- 項目：イベント名、開催日、場所（任意）、メモ（任意）
- 「現在のイベント」を 1 つ選ぶ。会計はそのイベントに記録される
- イベントが選ばれていないときは、会計画面に入れない

### F-04 在庫管理（MVP）
- 在庫を管理する商品には、イベントごとに **持ち込み数** を設定する
- 会計を確定すると在庫を減らし、取引を取り消すと戻す
- 残りが 0 になった商品は「売り切れ」と表示し、ボタンを押せなくする
- 残数は商品ボタンに表示する（例：残 3）
- 当日に追加で補充できるよう、持ち込み数は会期中でも編集できる

### F-05 会計（MVP）
- **商品選択**：カテゴリのタブを切り替え、商品ボタン（画像・商品名・価格）をタップしてカートに追加する
- **カート**：数量の増減、行の削除、全クリア
- **値引き**（6 章の計算ルールに従う）
  - 商品ごと：円の値引き、または % の値引き
  - 会計全体：円の値引き、または % の値引き
  - % 値引きのときは、**端数処理をその都度選べる**（6.2 参照）。選んだ方式ごとの値引き後金額を並べて表示し、見比べてから選べるようにする
  - **定型ボタン**：設定画面で登録した値引き（例：「100 円引き」「20% 引き」）をワンタップで適用できる。自由入力も併用できる
    - 定型ボタンが % の場合は、端数処理の初期選択が選ばれた状態で適用する。その場で別の方式に変えることもできる
- **お預かり**：テンキー入力と、クイックボタン（ぴったり / 1,000 / 5,000 / 10,000 円）
- お釣りを大きく表示する。お預かり額が合計に満たないときは確定できない
- **確定**：取引の保存と在庫の減算を、1 つのトランザクションでまとめて行う

### F-06 レシート画面（MVP）
- 会計を確定したら、レシート風の画面を表示する
- 表示内容：店名、イベント名、日時、取引番号、明細（商品・数量・金額）、値引き、税率別の対象額と内消費税額、合計、お預かり、お釣り
- 設定画面で入力した場合だけ表示する項目（空欄なら表示しない）
  - **インボイス登録番号**（T＋13 桁。入力時に形式をチェックする）
  - **連絡先**（電話番号、メールアドレス、住所などの自由入力テキスト）
  - **SNS・URL**（最大 3 件。それぞれラベル（例：Instagram）と URL を登録し、QR コードを表示する。QR コードは端末内で生成するので、オフラインでも表示できる）
  - **フッターメッセージ**（自由入力。例：「ありがとうございました」）
- インボイス登録番号を表示する場合は、適格簡易請求書の記載事項を満たすようにする。軽減税率（8%）の対象商品には「※」を付け、「※は軽減税率対象」と注記する
- 「次の会計へ」ボタンで会計画面に戻る
- 取引履歴からも再表示できる
- 印刷（`window.print()` と 58/80mm 用の印刷 CSS）は **後**。プリンタの実機検証が必要なため

### F-07 取引履歴・取消（MVP）
- イベントごとに取引の一覧を表示する（新しい順）
- 取引を取り消す（論理取消。記録は残し、集計から外し、在庫を戻す）
- 取り消した取引の、取消の取り消しはできない

### F-08 集計（MVP）
- **イベント別**：売上合計、取引件数、客単価、値引き合計、税率別の売上と内消費税額、取消件数
- **商品別**（イベントで絞り込み可）：販売数量、売上金額。販売数量順と金額順で並べ替えられる
- 時間帯別・日別・月別は **後**

### F-09 書き出し・バックアップ（MVP）
- **CSV 書き出し**（売上を Excel などで使うため）
  - 単位：**明細単位**（1 行 = 1 明細）
  - 対象：イベントを選んで書き出す（全イベント一括も可）
  - 文字コード：Excel で文字化けしないよう、UTF-8（BOM 付き）にする
  - 列（案）：イベント名、開催日、取引番号、取引日時、状態（有効 / 取消）、商品名、カテゴリ、単価、数量、明細値引き、全体値引きの按分額、値引き後金額、税率
  - 列の確定は「03-データ設計」で行う
- **JSON バックアップ**（このアプリに戻すため）：全データ（画像を含む）を 1 ファイルに書き出す
- **JSON 復元**：バックアップから全データを置き換える（実行前に確認ダイアログを出す）
- バックアップを促す通知は出さない。設定画面に、前回バックアップした日時を表示するだけにする

### F-10 PWA（MVP）
- ホーム画面に追加でき、全画面で起動する
- オフラインで起動できる（アプリ本体をキャッシュする）
- 新しいバージョンがあれば通知し、ユーザーの操作で更新する（会計中に勝手に再読み込みしない）

### F-11 設定（MVP）
- レシートの表示項目：店名、インボイス登録番号、連絡先、SNS・URL（最大 3 件）、フッターメッセージ（F-06 参照）
- % 値引きの端数処理の初期選択（切り捨て / 切り上げ / 10 円単位）
- 値引きの定型ボタン：登録・編集・削除・並べ替え（最大 8 件）
  - 項目：表示名、種類（円 / %）、値、使える対象（商品ごと / 会計全体 / 両方）
  - 初期登録：「50 円引き」「100 円引き」「10% 引き」「20% 引き」（すべて対象は両方）
- データの永続化の状態表示と、要求ボタン
- 全データの削除（二重確認）

## 6. 計算・データのルール

### 6.1 金額
- 金額はすべて **円単位の整数** で扱う（小数は使わない）
- 価格は税込みで登録する。税額は「内消費税」として計算する

### 6.2 値引き
- % 値引きの端数処理は、値引きを適用するたびに次の 3 つから選ぶ

  | 方式 | ルール | 例：555 円の 10% 引き |
  |---|---|---|
  | 切り捨て | 値引き額の 1 円未満を切り捨てる | 55 円引き → 500 円 |
  | 切り上げ | 値引き額の 1 円未満を切り上げる | 56 円引き → 499 円 |
  | 10 円単位 | 値引き後の金額を 10 円未満切り捨てにする | 65 円引き → 490 円 |

  - 対象は、商品ごとの値引きならその明細の金額、会計全体の値引きなら全体の値引き前合計
  - 初期選択は「切り捨て」。設定画面で、初期選択の方式を変えられる
  - 選んだ方式は取引データに記録する（あとで計算根拠を確認できるようにするため）
  - 円指定の値引きは端数が出ないので、選択欄を出さない
- 適用順：商品ごとの値引き → 会計全体の値引き
- 会計全体の値引きは、税率別の小計の比率で按分する。端数は小計の大きい税率に寄せる
- 値引き後の金額はマイナスにならない

### 6.3 消費税
- 税率ごとに、値引き後の税込合計から内消費税額を計算する
  `内消費税 = floor(税率別税込合計 × 税率 ÷ (100 + 税率))`
- 端数処理は **1 取引・1 税率ごとに 1 回**（適格簡易請求書のルールに合わせる）

### 6.4 取引のスナップショット
- 取引明細には、会計時点の商品名・単価・税率をコピーして保存する。あとで商品を編集しても、過去の取引や集計は変わらない

### 6.5 取引番号
- 形式：`MMDD-NNN`（開催日の月日 ＋ イベント内の 3 桁連番。例：`1103-012`）
- 連番はイベントごとに 001 から始まる。1,000 件目以降は 4 桁になる（`1103-1000`）
- 取り消した取引の番号は欠番として残し、使い回さない
- 同じ日に複数のイベントがある場合や、別の年の同じ日では番号が重複しうる。CSV と集計はイベント名・開催日と一緒に扱うので、区別できる

### 6.6 画像
- 長辺 400px 程度に縮小し、JPEG（または WebP）に圧縮して保存する（目安：1 枚 50KB 以下）
- 50 商品で約 2.5MB を想定する

## 7. 非機能要件

| 分類 | 要件 |
|---|---|
| 操作性 | 片手で操作できる。ボタンは指で押しやすい大きさ（44px 以上）にする。屋外でも見やすいコントラスト。縦画面を優先する |
| 性能 | 商品をタップしてからカートに反映されるまで 100ms 以内を目標にする。起動は 2 秒以内（2 回目以降） |
| 信頼性 | 会計の確定はアトミックに行う（途中で落ちても、取引と在庫が食い違わない）。アプリが落ちてもカートの内容を復元できる |
| 対応ブラウザ | iOS Safari と Android Chrome の、それぞれ直近 2 メジャーバージョン |
| セキュリティ | 外部に通信しない（アプリ本体の取得と更新を除く）。個人情報は扱わない |
| 言語 | 日本語のみ |

## 8. 対象外（今回のスコープに含めない）

- レシートの印刷、プリンタ連携（将来検討。F-06 参照）

- 複数端末での同期、クラウド保存
- ログイン、操作者ごとの記録
- 時間帯別・日別・月別の集計
- 多言語対応
